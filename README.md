# 켜켜이

지나온 지역을 채우고, 시간·장소·주제를 따라 기억을 탐색하는 로컬 개인 아카이브입니다. 사진 없이 제목 하나로 기억을 남길 수 있습니다. 원문과 사진은 브라우저 IndexedDB에만 저장됩니다. Life Hub에 연결하면 Claude가 제안한 기록을 받고, 켠 기기에서는 방문한 시도 격자(보드 타일)만 올립니다. 추억 제목·장소·사진은 올리지 않습니다.

https://kingjnu-sakayume.github.io/kyeokyeoi/

- **지도**: 독립 방문 확인이 기본입니다. 기억 분포 보기, 실제 경계 기반 점 레이어, 확대·이동·핀치, 전체 지역 검색·목록, 여러 곳 표시를 제공합니다. 모바일은 하단 패널, 데스크톱은 오른쪽 탐색 패널을 사용합니다.
- **시간**: 인생 시기와 연도별 보기. 직접 시기를 만들고 기억을 고르거나 선택적 연도 범위를 지정합니다. 불확실한 시기를 강제로 정확한 날짜로 바꾸지 않습니다.
- **기억**: 제목·본문 검색, 장소·시기·첫 경험·사진 필터, 작성순·경험 시점순 정렬, 텍스트 행 목록을 제공합니다.
- **컬렉션**: 같은 기억을 여러 주제로 묶습니다. 직접 만든 컬렉션과 조건에 따른 자동 모음을 구분합니다.
- **설정**: 별도 메뉴에서 테마 4종, 태어난 해, 백업 내보내기·합치기·임시 저장소 복원 시험에 접근합니다.

기존 `#/map`, `#/timeline`, `#/settings`, `#/memory/<id>` 주소와 브라우저 뒤로 가기를 유지합니다. `#/memories`, `#/collections`를 추가했습니다. 상세에서 같은 지역·연도·인생 시기·컬렉션·직접 연결한 기억으로 이동할 수 있습니다.

## 개발과 검증

Node 22 이상을 사용합니다.

```sh
npm ci
npm run dev
npm test
npm run lint
npm run build
npm run preview        # 빌드 결과(dist/)를 로컬에서 확인
npm run generate-icons # PWA 아이콘 다시 만들기 (scripts/generate-icons.mjs)
npx playwright install chromium
npm run test:e2e
```

빌드는 `dist/`에 생성합니다. main 배포 워크플로가 `scripts/copy-site.mjs`로 정적 파일을 `docs/`에 복사하며 문서는 보존합니다. PR에는 생성된 배포 산출물을 넣지 않습니다. 이미 설치한 Chromium을 사용할 때는 `PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH`로 실행 파일 경로를 지정할 수 있습니다. Vitest는 이름을 분리한 fake IndexedDB, Playwright는 테스트 origin의 격리된 브라우저 컨텍스트만 사용합니다.

## 데이터와 복구

DB는 기존 이름 `kkyeokyeoi-db`의 v3입니다. 기억·사진·설정은 그대로 두고 방문·컬렉션·인생 시기를 추가했습니다. 백업 형식 v3은 무결성 정보와 전체 아카이브를 보존하며 v2 백업도 읽습니다. [업그레이드·백업·다중 탭·복구 안내](docs/DATA_RECOVERY.md)를 확인하세요. 기본 화면이 열리지 않을 때는 같은 사이트의 `recovery.html`에서 원본을 보존할 수 있습니다.

지도 데이터는 기존 southkorea-maps의 2013 KOSTAT 경계 251개입니다. 현재의 모든 행정구역 개편을 나타내지는 않습니다. 기존 코드는 유지하며 알 수 없는 코드는 저장된 라벨로 표시합니다. 경계 재생성은 `npm run regions -- <원본 경계 JSON>`으로 수행합니다.

## Life Hub 연결

Life Hub에 연결하면 Claude가 제안한 추억·방문을 설정에서 확인하고 저장합니다(`src/integration/lifehub.ts`). 연결하지 않아도 앱은 로컬 저장소만으로 작동합니다. [Life Hub 계약과 Achievement 연결 정책](docs/LIFEHUB_INTEGRATION.md)에 원래의 설계 원칙이 있습니다.

## 보드 타일

[Life Board](https://github.com/KINGJNU-sakayume/board)에 보내는 타일 목록(규격 v1)입니다. 이 앱은 데이터만 만들고 모양은 보드가 정합니다.

| id | 이름 | 형태 | 크기 | 처음부터 보임 | 데이터 출처 |
|---|---|---|---|---|---|
| `regions` | 켜켜이 · 지역 방문 | map(시도 17칸) | 2x2(처음), 2x1 | 예 | 방문 기록의 지역 코드와 방문일(없으면 기록한 날) |

- **왜 이것만**: 지금 지도를 얼마나 채웠는지가 이 앱의 가장 큰 흐름입니다. 방문한 시도는 `on`, 가장 최근 방문한 시도는 `last`로 표시하고 "N곳 방문 · 마지막 11/5 서울"처럼 날짜로 적어 날이 지나도 틀리지 않습니다. 추억 제목·장소와 사진은 개인 기록이라 보내지 않으므로 비공개 기억도 나가지 않습니다.
- **칸 구성**: 시군구 251개는 보드 격자 한도(200칸)를 넘어 시도 단위로 묶었고, 배치(6열)와 시도 약칭(서울, 경기, 세종 …)은 코드 상수입니다(`src/integration/boardTiles.ts`). 예시 출력은 `board/sample.json`입니다.
- **언제 올리나**: 앱을 열 때와 방문·추억이 바뀔 때, 마지막 업로드에서 10분이 지났으면 바로, 아니면 10분이 차는 때 한 번 올립니다(10분에 한 번 이하). 마지막으로 성공한 내용(`generated_at` 제외 sha256)과 같으면 보내지 않지만, 보드가 '오래됨'(14일)으로 보지 않도록 하루가 지났으면 같아도 한 번 보냅니다. 앱이 닫히기 전에 못 보낸 것은 다음에 열 때 보냅니다. 연결되어 있지 않거나, 이 기기에서 꺼져 있거나, 기록이 하나도 없으면 올리지 않습니다.
- **어느 기기에서**: 설정 > Life Hub의 「이 기기에서 보드에 올리기」(기기별, 기본 꺼짐). Hub는 앱마다 최신 목록 하나만 보관하고 기록은 기기 안에만 있어, 여러 기기에서 켜면 서로 덮어씁니다. 한 기기에서만 켜 두세요.
- **다시 연결이 필요한 경우**: 이 기능 이전에 만든 연결에는 `kyeokyeoi:board` 권한이 없어 첫 업로드가 `insufficient_scope`(403)로 거절됩니다. 이때 연결은 끊지 않고(수신함·동기화는 그대로) 설정에 「보드에 올리려면 Life Hub에 다시 연결」 안내만 보여줍니다. 다시 연결하면 해소됩니다. 그 밖의 401·403은 기존처럼 연결이 끊긴 것으로 처리합니다.
- **실패할 때**: 네트워크 오류·5xx는 다음 기회에 다시 보냅니다. 400·413은 이 앱 쪽 문제라 같은 내용을 다시 보내지 않고 개발자 콘솔에만 남깁니다. 업로드 실패는 앱의 다른 기능을 막지 않습니다.
- **보내는 것과 저장 위치**: 보드용 목록만 보냅니다(기록 자체는 보내지 않음). 마지막 성공 sha·시각, '보낼 것 있음' 표시, 기기 설정은 이 브라우저의 localStorage에만 있습니다.
