# 켜켜이 2.0 구현 보고

2026-11-01 · 대상: `KINGJNU-sakayume/kyeokyeoi` · 브랜치: `codex/kyeokyeoi-2`

## 1. 기존 구조에서 발견한 문제

- 지도 색은 기억 수로 결정되는데 함수가 방문 수라는 이름을 사용했다. 방문만 등록할 방법이 없었다.
- 백업 가져오기가 한 파일 안의 중복 ID를 재검사하지 않아 같은 기억을 덮어쓸 수 있었다. 사진 ID 충돌과 소유 관계도 충분히 검사하지 않았다.
- 읽지 못한 사진을 가져오기에서 제외하면서 원래 참조까지 제거했다. 백업 설정은 태어난 해만 포함했고 무결성·실제 복원 비교가 없었다.
- v1 사진 변환 시 읽지 못한 사진을 무시할 수 있었고, 저장소 업그레이드의 차단·연결 해제·재시도·구버전 복구 안내가 없었다.
- 전체 앱이 최대 520px로 제한되어 데스크톱 지도 탐색 공간이 좁았다. 지도도 가로로 넓은 화면에서 위아래가 잘릴 수 있었다.
- 시간 화면만 있었고 기억 검색·직접 만든 시기·컬렉션은 없었다. 작성 화면의 선택 항목이 처음부터 모두 펼쳐졌다.
- 사진을 읽지 못할 때 목록·상세에 빈 이미지 요소가 남을 수 있었다. 태어난 해 설정을 처음 사용 시 건너뛸 수 없었다.
- 빌드 결과가 `docs/`를 비우므로 여기에 추가할 설계·복구 문서도 사라질 수 있었다.

## 2. 실제 구현한 기능

### 데이터 안정화

이름을 지정하는 로컬 Repository, 격리된 Vitest/fake-indexeddb 테스트, 사진·기억의 원자적 저장, 사진 ID 충돌 검사, 오래된 다중 탭 편집 방지를 추가했다. 출생연도 변경에 따른 추정 연도 계산도 같은 트랜잭션에서 처리하며 입력 원문과 작성·수정 시각은 보존한다.

백업 v3은 전체 설정·사진 Blob·소유 관계·기억·방문·컬렉션·시기와 SHA-256 무결성 정보를 포함한다. 임시 DB에서 복원한 데이터를 원본과 비교한다. 누락 사진은 원래 참조를 유지하며, 동일한 기억을 가져올 때 비어 있는 Blob을 복구할 수 있다. 다른 내용의 동일 ID는 자동 덮어쓰지 않는다. 충돌과 손상 결과를 화면에 남긴다. 복원 검증에 실패해도 원본 보존용 백업을 받을 수 있다.

### 지도와 방문

독립 방문 확인, 해제, 여러 지역의 일괄 표시·해제, 선택적 방문 날짜를 추가했다. 등록 시각을 방문 날짜로 쓰지 않는다. 기존 기억은 방문 확인 후보로만 안내한다. 방문 취소와 기억 삭제는 서로 영향을 주지 않는다.

기본 방문 지도와 보조 기억 분포 지도를 분리했다. 실제 SVG 경계에 점 패턴을 적용하고 확대하면 경계를 사용한다. 기존 251개 지역 경로와 전체 검색·목록을 보존했다. 선택한 지역과 지도 위치를 상세 열람 후 복원한다. 모바일 하단 패널과 데스크톱 오른쪽 패널을 제공한다.

### 네 탐색 화면과 기억

`지도 / 시간 / 기억 / 컬렉션`을 제공하고 설정은 별도 메뉴로 옮겼다. 시간은 인생 시기·연도별 탐색과 직접 만든 시기를 지원한다. 기억은 제목·본문 검색, 장소·시기·첫 경험·사진 필터, 작성순·경험 시점순 정렬과 50개씩 확장하는 텍스트 목록을 제공한다. 컬렉션은 같은 기억을 여러 모음에 담으며 자동 모음과 구분한다.

기억 작성은 제목과 선택적 본문을 먼저 보여 주고 세부 항목은 접어 둔다. 나이·학년은 출생연도 없이도 입력할 수 있다. 상세는 제목·본문을 우선하고 사진은 실제 데이터가 있을 때만 표시한다. 관련 지역·연도·사용자 시기·컬렉션·직접 연결한 기억으로 이동할 수 있다. 기존 상세 URL과 네 테마를 유지했다.

### PWA와 복구

자동 새로고침 대신 사용자가 적용하는 업데이트 알림을 사용한다. 앱·지도·폰트를 사전 캐시한다. 업그레이드 차단 상태를 로딩 중에도 안내하고 다른 탭의 버전 변경 때 연결을 닫는다. 호환 가능한 상위 버전은 DB 버전을 낮추지 않고 연다.

정적 `recovery.html`은 기본 앱과 독립적으로 현재 DB를 읽는다. 버전을 올리지 않고 원본 보존 백업을 내보낸다. v1 변환 오류가 있으면 원래 base64 데이터의 별도 복구 형식을 보존한다. 복구 정책은 [DATA_RECOVERY.md](DATA_RECOVERY.md)에 있다.

## 5. 기존 기록 보존 검증

실제 사용자 브라우저 저장소에 접근하거나 데이터를 이전하지 않았다. 별도 fake IndexedDB와 테스트 브라우저의 합성 fixture로 검증했다.

v2 DB의 원래 기억 ID·본문·사진 바이트·이전 지역 코드·시기 표현·설정을 읽고 v3에서 유지함을 확인했다. 사진 없는 기억 120개와 자유 입력 시기, 사진 포함 백업, 고아 Blob, 누락 사진, 내용이 다른 중복 ID, 사진 소유 관계 불일치, 반복 가져오기, 손상 해시를 검증했다. v1의 잘못된 사진 때문에 업그레이드가 실패해도 원본 DB 버전과 기록을 유지함을 확인했다. 방문 취소 후 기억, 기억 삭제 후 방문도 보존된다.

## 7. 미구현·검증 한계

- 실제 Life Hub·Supabase·ChatGPT·Claude 연동은 요구대로 구현하지 않았다. API가 존재하지 않아 계약과 연결 정책까지만 제공한다.
- 현재 행정구역 전체를 최신 경계로 갱신하지 않았다. 기존 2013 데이터와 저장 코드를 보존하며, 불확실한 코드 변환을 하지 않는다. 향후 명시적인 분할·통합 대응표가 필요하다.
- v1 원본 보존용 복구 파일의 일반 가져오기는 지원하지 않는다. 사진 변환이 실패한 경우 원본을 보존하고 오류 원인을 해결한 복구 버전에서 처리한다.
- Safari·Firefox·실제 iOS/Android 기기, 저장 공간 부족을 강제로 발생시키는 실기기 시험은 이번 환경에서 수행하지 않았다. 브라우저 검증 범위는 Chromium과 모바일 터치 에뮬레이션이다.
- 브라우저 밖 동기화·삭제 전파·외부 입력 중복 방지 원장은 미래 계약 확정 후 구현할 대상이다.

## 9. Life Hub를 위해 남은 작업

원본 서비스와 안정적인 원본 ID, 수정 버전, 사용자 확인과 AI 추정의 구분, 방문·기억·활동 링크 타입을 정의했다. 향후 실제 API·인증·권한, 원본 키 유일성, 수신 검증기, 재시도 중복 방지, 충돌 비교 UI, 삭제·철회 정책과 오프라인 전송 큐가 필요하다.

일상 활동은 Achievement만 원본으로 남긴다. 사용자가 선택한 의미 있는 경험만 기억으로 연결한다. 방문 확인을 행동 업적 달성으로 사용하거나 같은 경험을 두 번 활동으로 집계해서는 안 된다. Achievement의 평가 엔진을 바꾸지 않는다. 자세한 내용은 [LIFEHUB_INTEGRATION.md](LIFEHUB_INTEGRATION.md)에 정리했다.
