# 저장소 업그레이드와 복구

## 변경 범위

IndexedDB 이름은 기존 `kkyeokyeoi-db`를 유지하고 스키마 버전은 **2 → 3**으로 올린다. v2 → v3에서는 `regionVisits`, `collections`, `lifePeriods` 저장소만 만든다. 기존 기억, ID, 사진 Blob, 설정, 이전 지역 코드, 원래 시간 표현을 다시 쓰지 않는다. 기존 기억으로 방문을 자동 확정하지 않는다.

v1 사진 변환은 같은 버전 변경 트랜잭션 안에서 수행한다. 사진을 읽지 못하면 전체 업그레이드를 중단하고 원래 v1 데이터와 버전을 보존한다. 오류를 무시하고 사진을 버리지 않는다.

## 백업 v3

DB 버전과 백업 버전은 독립적이다. `app`, `version`, `exportedAt`과 기억·사진 data URL·사진 소유자·모든 설정·방문·컬렉션·시기를 포함한다. SHA-256은 날짜/봉투 정보를 제외한 정렬된 데이터 payload에 적용한다. 서명·인증 목적의 해시가 아니라 손상 탐지 정보다.

- v2 JSON은 계속 가져올 수 있다. 기록 원문과 공개 여부를 포함한 기존 필드는 그대로 보존한다.
- 동일 ID의 다른 기억·사진·방문·모음은 기존 값을 유지하고 충돌을 보고한다.
- 같은 파일 안에 내용이 다른 중복 ID가 있으면 가져오기 전 중단한다.
- 사진이 누락되거나 읽을 수 없어도 원래 `photoIds`를 지우지 않는다. 동일한 기억을 다시 가져올 때 비어 있는 사진 Blob만 복구할 수 있다.
- 무결성 불일치는 쓰기 전에 거부한다. 사진 소유 관계 불일치와 ID 충돌은 보고하며 기존 사진을 덮어쓰지 않는다.
- 사진 원본에 고아 Blob이 있으면 백업에 포함한다. 서로 다른 기억이 잘못 공유한 사진도 한 기억 삭제만으로 제거하지 않는다.
- 설정의 기존 값은 유지하고 비어 있는 값만 가져온다. 가져온 테마·출생연도는 UI에 반영한다.
- 컬렉션·시기는 ID 참조를 보존한다. 삭제된 기억의 참조도 임의로 다른 기억에 연결하지 않는다. UI는 현재 존재하는 기억만 보여 준다.

설정의 내보내기는 별도 임시 DB에 실제 복원하고, 기록·참조·설정·사진 바이트까지 비교한 결과를 보여 준다. 임시 DB는 종료 후 삭제된다. 손상된 원본 때문에 복원 비교에 실패하면 **원본 보존용 백업**을 내려받되 검증 실패를 명시하고 성공한 백업 날짜로 기록하지 않는다.

## 다중 탭과 PWA

- 저장소 업그레이드가 다른 탭 때문에 막히면 로딩 화면에서도 원인과 다른 탭을 닫는 방법을 표시한다.
- 새 코드의 탭은 `versionchange` 때 연결을 닫아 다른 탭의 업그레이드를 허용한다.
- 연결 실패는 Promise를 재설정하여 재시도할 수 있다. 예기치 않은 종료도 안내한다.
- 호환되는 더 높은 스키마는 버전을 낮추지 않고 열고 필요한 저장소 존재를 확인한다.
- 오래된 v2 코드의 `openDB(name, 2)`는 v3 DB에서 `VersionError`를 낼 수 있다. 이미 설치된 옛 코드를 소급 수정할 수는 없다. 해당 탭을 닫고 새 버전으로 다시 열어야 한다.
- 서비스 워커는 새로고침을 강제하지 않는 prompt 방식이다. 기억 입력 시트가 열려 있을 때 업데이트 버튼을 숨긴다. 앱 셸·지도·폰트는 사전 캐시한다.
- 같은 기억을 여러 탭에서 고치면 먼저 저장된 내용을 기준으로 `updatedAt`을 확인한다. 오래된 편집은 거부하고 입력을 남긴다. 백그라운드에서 기록을 다시 읽어도 작성 중인 초안을 초기화하지 않는다. 미래 네트워크 동기화를 대신하는 기능은 아니다.

## 실제 복구 경로

1. 저장소를 삭제하거나 브라우저 데이터를 초기화하지 않는다.
2. 다른 켜켜이 탭을 닫고 최신 버전을 다시 연다. 기존 v2 버전으로 단순 롤백하면 v3 DB를 읽지 못할 수 있다.
3. 기본 앱이 열리지 않으면 같은 origin/경로의 **`recovery.html`**을 연다. 기본 앱과 별도의 정적 화면이며 DB 버전을 지정하지 않고 읽기 전용 트랜잭션으로 연다. DB가 없으면 생성도 중단한다.
4. v2 이상은 정상 가져오기에 사용할 수 있는 백업 v3을 내보낸다. 복구 화면은 복원 검증을 수행하지 않으므로 새 앱의 ‘백업 파일 복원 시험’에서 먼저 검사한다. 새 스키마의 알 수 없는 저장소를 일반 백업 v3에 자동 해석하지는 않는다.
5. 손상된 v1은 base64 원본이 있는 `kyeokyeoi-recovery` 보존 파일을 만든다. 이것은 일반 백업과 구별되며 일반 가져오기에 넣을 수 없다. 실패한 변환 규칙을 수정한 복구 버전에서만 사용한다.
6. 배포 롤백은 DB v3을 이해하는 이 변경의 데이터 계층과 복구 화면을 유지해야 한다. 기존 v2 코드 전체를 다시 배포하는 방식은 사용하지 않는다.

복구 화면도 처음 배포 전에는 옛 서비스 워커 캐시에 없을 수 있다. 그 경우 네트워크가 연결된 상태에서 한 번 열어야 한다. 브라우저 저장소가 이미 삭제되었거나 Blob 자체가 손실된 경우, 별도 백업 없이 사라진 바이트를 복구할 수는 없다.

## 지역 코드

지도는 기존 2013년 KOSTAT 경계 251개를 유지한다. 군위군의 대구 소속 등 기존 표시 보정도 유지한다. 최신 행정구역으로 불확실한 자동 변환을 하지 않는다. 지도에서 찾을 수 없는 코드도 원문·라벨을 보존하고 기억 색인에서 찾는다. 향후 경계 데이터 갱신 시에는 분할·통합의 명시적 대응표와 사용자의 확인 절차가 필요하다.
