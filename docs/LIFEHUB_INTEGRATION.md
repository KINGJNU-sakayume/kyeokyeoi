# Life Hub 연결 계약 (초안 v1)

이 문서는 아직 존재하지 않는 Life Hub와의 연결 지점을 정의한다. 서버, Supabase 인증, 동기화 작업, ChatGPT·Claude API 호출은 구현하지 않는다. 켜켜이는 네트워크 없이 로컬 저장소만으로 작동한다. Achievement 저장소는 수정하지 않았다.

## 계약과 저장 위치

- `src/integration/contracts.ts`: `ArchiveEnvelope`, `ArchiveLink`, `sourceKey`.
- `src/db/model.ts`: 원본 ID, `SourceReference`, 기억·방문 타입.
- `src/db/index.ts`: 이름이 지정된 로컬 Repository. UI는 이 API를 사용한다. 향후 인증·전송 계층은 이 밖에 추가한다.
- 로컬 `Memory.id`와 `RegionVisit.id`는 생성 후 유지한다. 외부 ID로 원래 ID를 교체하지 않는다.
- 외부 키는 `(service, originalId)` 두 필드를 함께 사용한다. 서비스명/ID에 구분 문자가 있어도 충돌하지 않도록 튜플로 직렬화한다.
- `revision`은 외부 원본 수정 버전이다. `updatedAt`이나 기록한 날짜와 같은 의미가 아니다.
- `certainty`는 `confirmed` 또는 `inferred`. 전송자와 실제 확인 주체를 혼동하지 않는다. 사용자 확인은 별도 `confirmedByUser`에 남긴다.
- 제목·본문·원래 시간 표현·지역 코드·사진 참조는 원본대로 보존한다. 나이·학년 환산 `computedYear`는 검색용 추정 값이다.

## 입력 및 충돌 정책

1. 수신 레이어는 계약 버전, 필수 필드, 사진 소유 관계와 실제 사용자 동의를 검사해야 한다.
2. `idempotencyKey`는 재시도에도 유지한다. 외부 원본 키와 버전을 함께 비교한다. 현재 로컬 백업 가져오기와 외부 수신 API를 혼용하지 않는다.
3. 같은 원본 키·같은 버전·같은 내용은 다시 만들지 않는다. 같은 버전인데 다른 내용이면 충돌이다.
4. 높은 버전은 자동 덮어쓰지 않는다. 로컬 편집과 원본 변경을 사용자에게 비교한 뒤 명시적으로 반영한다. 낮은 버전은 기존 내용을 유지한다.
5. AI가 추정한 시기·지역은 원본 메타데이터에 남길 수 있으나 방문 확인을 생성해서는 안 된다. 사용자 확인 전에는 제안으로만 취급한다.
6. 방문은 사용자의 독립적인 확인이다. 기억의 장소, 위치 추정, 활동 링크가 방문 확인을 대신하지 않는다. `recordedAt`을 실제 `visitedOn`으로 복사하지 않는다.
7. 삭제 전파와 tombstone은 아직 구현하지 않았다. 외부 삭제 때문에 로컬 기억·사진·방문을 자동 삭제하면 안 된다.

## Achievement와 같은 경험 연결

| 상황 | 저장·집계 정책 |
| --- | --- |
| 일상 활동 | Achievement만 원본으로 유지 |
| 사용자가 기억으로 남기기로 선택 | 켜켜이에 기억 생성, `inspired-memory` 관계로 원본 활동 참조 |
| 두 서비스가 같은 경험을 다룸 | `same-experience` 관계와 안정적인 원본 ID로 중복 집계 방지 |
| 지역 방문 확인 | 켜켜이 방문만 변경. 특정 행동 업적 달성으로 해석하지 않음 |
| 방문·기억·활동 관계 | 링크로 연결하고 원문을 반복 복제하지 않음 |

Achievement의 평가 엔진은 그대로 둔다. 미래 집계자는 `(service, originalId)` 또는 사용자가 확인한 `same-experience` 그룹을 한 번만 집계해야 한다. 연결 관계 자체가 행동 수행 증거는 아니다.

## 향후 필요한 구현

실제 Life Hub 스키마·API·인증과 사용자 권한, 원본 키 유일성 인덱스, 수신 검증기, 중복 방지 원장, 충돌 비교 화면, 삭제·철회 정책, 오프라인 전송 큐를 계약 확정 후 구현한다. Supabase RLS·로그인·사진 권한은 서버 계약에 맞춰 별도로 검증한다. 이 PR에는 가짜 로그인·동기화 성공 표시나 임의의 외부 endpoint가 없다.
